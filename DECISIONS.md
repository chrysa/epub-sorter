## Documented design decisions (reconstructed — INFERENCE from repo state)

The following are load-bearing decisions evidenced in the code but not previously written up
as ADRs. Recorded here for traceability; **UNKNOWN** whether they were ever formally ratified.

### D-A — `Common` base class, thin front-ends
`Cli` and `Gui` both inherit a single `Common` engine (`common.py`); all filesystem and
metadata logic lives there and only that module is coverage-gated. Evidence:
`pyproject.toml [tool.coverage.run].source = ["common.py"]`, class definitions in
`cli.py`/`gui.py`.

### D-B — Duplicate detection by exact identifier only
Deduplication keys on `metadata.identifier` (ISBN/UUID); no fuzzy or content-hash matching.
Evidence: `identifier_list` logic in `cli.py`/`gui.py`; flagged as the main limitation in
`docs/reference/github-inspiration.md`.

### D-C — Python 3.14 + test-only container
Runtime targets Python `>=3.14`; there is a `Dockerfile.test` but no runtime/production
container or compose file. Evidence: `pyproject.toml`, `Dockerfile.test`. This is consistent
with a local desktop tool rather than a deployed service.

### D-D — Windows `.exe` distribution via PyInstaller
A `build` extra pins PyInstaller and `build.ps1` produces a Windows executable. Evidence:
`pyproject.toml [project.optional-dependencies].build`, `build.ps1`.

### D-0012 (referenced, not defined here) — generated context files
`llms-full.txt`, `context-map.json`, `ai-instructions.md` are generated by
`scripts/gen_context_files.py` and must be regenerated, not hand-edited. Evidence: generated
file headers. Full ADR text lives in chrysa shared standards, not in this repo.
